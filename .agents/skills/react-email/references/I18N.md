# Internationalization

Localization belongs to the product's existing message and locale owner. React Email consumes the resolved contract; it does not establish a second translation system.

## Contract

- Pass an explicit, validated locale or a pre-resolved message object into the template.
- Reuse the application's message keys and formatting library when that code is safe in the render environment.
- Format dates, numbers, currencies, and plural forms with the requested locale and time zone. Do not rely on the rendering machine's defaults.
- Set document language and direction from the resolved locale.
- Keep transactional facts, URLs, identifiers, and provider metadata separate from translated prose.

## Layout

Allow for text expansion, longer action labels, and right-to-left ordering. Avoid fixed heights and image-based text. Preserve a logical reading order in both HTML and plain text.

## Verification

Render the default locale, the longest supported translation, and every RTL or locale-specific branch. Verify missing-key behavior, date and currency output, subject and preview text, plain-text order, and accessible link meaning.
